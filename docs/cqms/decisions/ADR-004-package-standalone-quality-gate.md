# ADR-004: Give `packages/ui`/`packages/api` their own full quality gate

**Status:** Accepted

## Context

ADR-003 gave `packages/ui`/`packages/api` their own `tsconfig.json` so they typecheck and lint standalone. But they still couldn't **test** standalone — Vitest needs a `vite.config.ts` to know the StyleX/Babel transform pipeline (for `packages/ui`'s `.tsx`/`.stylex.ts` files) and the test runner itself, and neither package had one. Their tests only ran via `apps/react-router`'s Vitest `include` being widened to reach into both packages (ADR-001/ADR-002) — a borrowed harness, not independent infrastructure. With almost all of `apps/react-router`'s original content now living in these two packages, it was worth finishing the job before continuing with other CQMS work.

## Decision

1. **Mirror the app convention exactly, not a bespoke setup.** Both packages get their own `vite.config.ts` + `config/` subdirectory (for `packages/ui`) at the **same directory depth** as `apps/<name>/config/*.ts` relative to the repo root — this matters because `@repo/vite-configs`'s `createReactRouterPluginsConfig` computes its self-referencing `@repo/ui/*` StyleX alias via a hardcoded `'../../../packages/ui/src/*'` relative to the caller's `appRootUrl`, assuming an `apps/<name>/config/` depth. Matching that depth (`packages/ui/config/`) means the existing shared factory works unmodified.
2. **`packages/api`** — minimal, matching `apps/api-server`'s pattern (no React/StyleX): `createFmtConfig()` + `createApiLintConfig()`, no `plugins` key at all.
3. **`packages/ui`** — matching `apps/react-router`'s pattern, with two deliberate deviations: `createFrontendLintConfig()` instead of `createReactRouterLintConfig()` (this package isn't a React Router app — no routes, so the route-specific overrides in the latter, e.g. `react/only-export-components: off` for `**/root.ts`, don't apply and would be dead configuration); and `createReactRouterPluginsConfig({ withReactRouterPlugin: false, withFixReactRouterAssetsPlugin: false })` — StyleX and the React Compiler Babel plugin still apply (this package's components need both), but there's no dev server or build to route/fix assets for.
4. **Both packages' own `resolve.alias` needed the self-referencing `@repo/ui`/`@repo/api` → `./src` entry**, same as every consuming app already has (ADR-001/003) — discovered by actually running `vp run test` inside `packages/ui`, which failed with "Cannot find package '@repo/ui/...'" on its own internal imports. tsconfig `paths` (ADR-003) only helps `tsc`/editors; Vite/Vitest's own bundler-level resolution needs the explicit alias regardless of which package the config lives in.
5. **`vite-plus` rejects a `package.json` script and a `run.tasks` entry sharing the same name** — discovered empirically ("Task `@repo/api#test` conflicts with a package.json script of the same name"). Matches `apps/react-router`'s own existing convention, which has no `"test"` script either (only `"test:watch"`) — `vp run test` is the intended invocation, not a same-named wrapper script. Both packages' `format`/`lint`/`typecheck` scripts stay, `test` was dropped.
6. **Real `package.json` dependency corrections**, discovered by actually running each script rather than assuming: both packages needed `vite-plus` itself (for `defineConfig`); `packages/ui` needed the full set of Babel/StyleX tooling packages `apps/react-router` already declares (`@babel/preset-typescript`, `babel-plugin-react-compiler`, `vite-plugin-babel`, `@stylexjs/eslint-plugin`, `@stylexjs/unplugin`) — because Babel and oxlint resolve preset/plugin specifiers relative to **the files being transformed/linted** (i.e. `packages/ui`'s own files), not relative to `@repo/vite-configs`'s own code, so each package that gets its files processed this way must independently declare these, exactly as `apps/react-router` already does.
7. **`apps/react-router`'s widened Vitest `include`** (ADR-001/002, reaching into `packages/ui`/`packages/api`) is now **removed** — it was a bridging workaround for packages that couldn't test themselves; keeping it would just run the same ~1330 tests twice (once per package's own `vp run test`, once via the app's borrowed harness) for no benefit.

## Consequences

- `packages/ui`, `packages/api`, and `apps/react-router` are now three fully independent quality-gated units — each runs `vp fmt` / `vp lint` / `tsc --noEmit -p tsconfig.app.json` / `vp run test` from its own directory with zero dependency on another package's harness.
- `apps/react-router`'s own test suite shrank to its true size: **1 file, 1 test** (`Root.component.test.tsx`) — an accurate reflection of how little app-specific logic remains there after ADR-001/002's extraction, not a regression.
- Any future workspace package that needs a full standalone quality gate (not just typecheck) should follow this same recipe: `vite.config.ts` (+ `config/` subdirectory at matching depth if it needs the shared plugins factory), a self-referencing `resolve.alias` entry alongside the `tsconfig.json` one from ADR-003, real `package.json` dependencies for whatever its own `types` array and transform pipeline pull in, and no `package.json` script sharing a name with a `run.tasks` entry.

## Verification performed

`packages/api`: `vp fmt --check`, `vp lint`, `tsc --noEmit -p tsconfig.app.json`, `vp run test` — all clean, standalone, 1 test file / 8 tests. `packages/ui`: same four commands, standalone, 315 test files / 1322 tests (the full suite, running entirely within the package's own process). `apps/react-router` re-verified after removing the now-redundant widened `include`: fmt/lint/typecheck clean, 1 test file / 1 test. Real dev server smoke test (200 response, correct HTML) re-run after the `vite.config.ts` change to confirm no runtime regression beyond what typecheck/lint/test would catch.
