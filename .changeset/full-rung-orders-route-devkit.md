At the `full` profile the application's page reads its table from Postgres. The loader passes the request's sort, filters and grouping to `@lcabrera/server`'s table-page reader, so `ORDER BY` and `WHERE` resolve them, and every column the read accepts offers sorting and filtering. A resource route answers each further page from a keyset cursor. A group row opens that group's rows in a dialog, and each row's menu deletes the row through an action, after which the page reads again. The page's column declarations, row type, loader, page reader, view, route table and its two tests replace the `monorepo` files at the same paths. `RUNG_RETIREMENTS` in `./config` now retires the `monorepo` page's module of rows and the test of its reader at `full`, so a tree moved up removes both when it has not edited them. The route ships four tests: two that run under `test:all` with the read mocked and fail on a loader that drops the sort or the filters, a column test, and one gated on `SMOKE_DB` that holds the sorted, filtered, paged, drilled and deleted answers to plain SQL over the seeded table. At `monorepo` every column still declares sorting and filtering off.
