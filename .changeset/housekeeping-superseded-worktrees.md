'@lcabrera/repo-standards': minor
---

`repo-housekeeping-prune` now judges a dirty worktree by content. Its line in the plan counts the changed files whose content matches the default branch's history, the worktree's own history, or neither, plus its untracked files. With `--apply --include-superseded` it removes a dirty worktree only when none match neither and nothing is untracked; no flag removes one holding a change found in neither history. A dirty worktree on a branch whose pull request is open, or with no pull request data, is kept even when every change is in history, and a branch any forced removal touches is not deleted in the same run. A change to a file's mode counts as matching neither history. An uncommitted deletion counts as matching only where that history once held the path and no longer does, and a detached worktree is removed as superseded only when a branch, tag or remote that this run does not delete contains its commit. Without the flag a dirty worktree is still only reported.

A clean worktree detached on a commit the default branch contains is now removed, a locked worktree is kept, a worktree whose status, HEAD or history lookup cannot be read is kept and names the failed read, and a clean worktree removed in a run no longer stops that run from deleting its merged branch; a superseded one keeps its branch. `--apply` runs `git worktree prune` before deleting any branch, so a branch a stale entry still names is deleted as planned, and the dry run lists those stale entries under their own heading. The checkout the command runs from is never touched.

The plan also lists containers labelled `devkit.throwaway`, whose value names the worktree that started them. `--apply` removes a stopped one, and a running one whose worktree is gone; a running one whose worktree is still there is listed under KEEPING with that reason. A running container whose worktree this plan removes is removed after it. The label is read whole, so a path holding a comma or an equals sign is matched as written, and a container whose label cannot be read is kept. Without Docker it lists none and says so; `REPO_STANDARDS_NO_DOCKER` set to any non-empty value turns the container checks off, and `REPO_STANDARDS_DOCKER` names the docker executable by absolute path. When no pull request list arrives on stdin, every worktree whose verdict needs one is listed as kept, with a note saying why.

New `--hint [--threshold <n>] [--advice "<text>"]` mode: one line when more than `n` worktrees (ten by default) look removable from local refs alone. The line ends with the advice text; without `--advice` it names `gh pr list --state all --json number,headRefName,state --limit 400 | npx --no -- repo-housekeeping-prune`, which prints the full plan in a repository that installed this package. It reads no stdin, calls neither `gh` nor Docker, and removes nothing, so a session-start hook can run it.
