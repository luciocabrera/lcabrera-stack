The `full` profile now places its own asset group, so it no longer prints "nothing above `monorepo` ships". On top of everything `monorepo` places it adds a local Postgres lane: a `docker-compose.yml` in docker/local and its `.env.example` template, the `enterprise_orders` DDL with a deterministic 1,000-row demo seed, and a seed runner in the application (`seed-db.mjs`). The runner uses `pg` directly, creates the database when it is missing, and applies the DDL in one transaction. The application declares `@lcabrera/server` and gains `seed` and `test:smoke` tasks. Its database tests gate themselves on `SMOKE_DB`, so a run with no database skips them. `create --profile full` writes four root tasks, tagged to the `full` rung: `db:up`, `db:down`, `db:status` and `db:seed`. A tree that holds the blueprint and syncs at `full` gains the same four. The template holds placeholders only, the compose file has no default for a credential, and the workspace `.gitignore` now ignores `.env` and `.env.*` but keeps `.env.example`. Two files are replaced at the same path under `full`: the application's `package.json` and `COMMANDS.md`, which documents the database tasks. A new `paths.full` key places the group, and it defaults to the repository root. `placementNotice` and `rungPlacedAs` in `./config` take an optional profile map as a second argument.
